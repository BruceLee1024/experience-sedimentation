> 编写日期：2026-08-02（基于当时仓库代码通读）

## 一、项目定位

面向**个人工程造价师**的本地优先造价数据管理工具。把散落在硬盘里的历史 Excel（广联达及其他来源）转化为**可检索、可比较、可追溯、可复用**的个人造价数据库。

一句话：**给造价师的 Excel 仓库装上数据库。**

### 核心产品原则（来自 PRODUCT.md）

| 原则 | 含义 |
|---|---|
| 证据先于结论 | 价格、指标、匹配、AI 建议都能就地查看来源、口径和计算过程 |
| 异常优先处理 | 批量导入聚焦少数需判断的异常项，不要求逐行确认正常数据 |
| 熟悉但更清晰 | 保留造价软件用户熟悉的表格、树形层级、批量操作心智 |
| 对比辅助决策 | 差异、风险、置信度、不可比原因比单一推荐更醒目 |
| 人拥有最终决定权 | AI 提供候选、理由和不确定点，不代替用户确认正式数据 |

### 现状（V0.1 技术预览）

- ✅ 需求访谈、架构选型、确定性核心闭环、DeepSeek 适配器、备份、arm64 打包
- ⚠️ 尚无真实广联达脱敏样本，解析器未经真实数据校准，**不能标记正式 V1**

## 二、总体架构

```
┌─────────────────────────────────────────────────────┐
│ 前端 React SPA（Vite/TS，同源静态托管）              │
│ 总览/项目库/导入/跨库工作台/清单库/工料机库/定额库/   │
│ 质量中心/清单匹配/标准化规则/备份与AI —— 11 个视图    │
└───────────────┬─────────────────────────────────────┘
                │ REST /api/v1（FastAPI，127.0.0.1:8765）
┌───────────────┴─────────────────────────────────────┐
│ 后端服务层（Python 3.13 / uv / SQLAlchemy 2.0）       │
│ 导入解析 · 检索 · 匹配 · 比较 · 指标 · 质量 · 备份    │
│ AI 适配器（DeepSeek：意图解析/候选审查/映射建议）     │
└───────┬───────────────────────────┬─────────────────┘
        │                           │
┌───────┴─────────┐     ┌───────────┴──────────────┐
│ 中心库 SQLite    │     │ 3 个业务分库 SQLite        │
│ cost-data.sqlite3│     │ catalog(清单)/resource(工料机)│
│ 项目/版本/导入/  │     │ /quota(定额) — 发布时镜像， │
│ 清单/定额/指标/  │     │ 独立只读检索               │
│ 规则/审计/授权   │     └──────────────────────────┘
└─────────────────┘
```

**关键设计：中心库 + 三业务分库。** 项目、导入、源文件等元数据存中心库；用户可见的清单/工料机/定额数据在发布时镜像到独立 SQLite 文件。分库用 UUID 引用而非跨库外键，服务层读取时解析。好处：发布后的检索库干净、独立、可单独备份校验。

## 三、核心业务闭环

### 1. 导入 → 发布（事务性）

```
上传 Excel(.xlsx/.xlsm) → SHA256 归档去重
→ openpyxl 解析（表头别名映射、多行表头识别）
→ 待确认映射 mapping_review（可请求 AI 建议，可保存解析模板 ParserProfile）
→ 解析 → 异常复核（error 阻断 / warning 提示，均可忽略并记录原因）
→ 质量报告（决定是否可发布）
→ 发布（单事务）：算指标 → 重建 FTS 索引 → 镜像三个分库 → 旧版标记 superseded
```

- 源文件按 SHA256 归档到 raw/，重名/重复文件自动识别（DUPLICATE_FILE）
- 未识别内容不会静默进入正式数据（异常必须复核）
- 发布是**事务性**的：任一步失败则整个事务回滚，新版本对外不可见

### 2. 检索

- 中心库 FTS5 全文检索 + 结构化过滤（地区/专业/计价体系/成果阶段/单位/价格区间/数据类型/项目类型）
- 跨库工作台统一检索清单库、工料机库、定额库，分库 Tab 各自独立检索
- 每条记录带来源：文件 → 工作表 → 行号 → 单元格（SourceRef 全链路可追溯）

### 3. 匹配（新清单项找历史价格）

- rapidfuzz 确定性召回 + 多因子评分（评分组成可解释，显示排除原因）
- 匹配会话（MatchSession）记录每次决策（接受/拒绝/无匹配）
- 确认接受时可"记住规则"——自动生成同义词标准化规则，下次更准

### 4. 比较与指标

- 多清单项比较：样本数、min/median/max、可比性警告
- 项目指标（ProjectMetric）：公式 + 分子分母来源可追溯，支持自定义模板
- 同类项目标杆（Benchmark）：对可比项目（画像齐全）按指标给出 P25/P50/P75 基准

### 5. 标准化主数据

- 名称/分类规则（NormalizationRule：同义词/单位/分类/禁止匹配）
- 单位换算（UnitConversion，带换算依据）
- 指标模板（MetricTemplate）
- 原则：**原始值永不覆盖**，标准名称、换算、规则全部可追溯

### 6. 备份与恢复

- SQLite backup API 在线快照（中心库+三分库）+ raw 原始文件 + manifest（SHA256 校验 + PRAGMA integrity_check）
- 自动备份：每日 + 每周（周一），保留策略（日 7 / 周 4）
- 恢复：先校验 → 写 pending-restore 标记 → 重启时应用（应用前自动留 pre-restore 紧急副本）

## 四、AI 层（DeepSeek 适配器）

三个能力，**全部可选、全部需授权、全部可审计**：

| 能力 | 用途 | API |
|---|---|---|
| search_intent | 自然语言 → 结构化搜索条件 | POST /ai/search-intent |
| candidate_review | 匹配候选审查建议 | POST /ai/candidate-review |
| import_parsing | 导入字段映射建议 | POST /imports/{id}/ai-mapping-suggestion |

- **授权机制**：每个能力独立 consent（AIConsent），可预览脱敏后的外发内容再确认，可"记住"授权
- **脱敏**：redact_payload 自动打码 项目名/客户/建设单位/api_key 等敏感字段
- **审计**：每次调用记录 AICall（能力/模型/延迟/错误/请求响应）
- **密钥**：只存 macOS Keychain（keyring），不落盘；不配置 AI 完全不影响核心功能
- **数据口径**：所有金额用 定长整数 + scale（fixedpoint）存储，杜绝浮点误差

## 五、安全与本地优先

- 无账号、无云同步，数据全部本机（`~/Library/Application Support/cost-data/`）
- 本地会话令牌：启动时随机生成（secrets.token_urlsafe），前端 bootstrap 获取后写 sessionStorage，非安全方法需带 `X-Cost-Data-Token`
- Origin 校验：仅允许 127.0.0.1/localhost 的 HTTP origin
- TrustedHost 中间件白名单
- AI 外发三层防护：授权 → 脱敏 → 审计

## 七、数据模型核心表

| 域 | 表 |
|---|---|
| 项目 | Project、ProjectVersion（版本号唯一，草稿→发布→superseded） |

| 系统 | AuditEvent（审计）、AIConsent、AICall、AppSetting |
